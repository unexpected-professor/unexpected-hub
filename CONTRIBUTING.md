# Contributing

The Unexpected Professor is currently a personal project in its planning
phase. Discuss substantial contributions before implementation so that public
content, course boundaries, accessibility, and licences remain coherent.

## Public-boundary requirements

Before contributing, read
[`documentation/public-boundary.md`](documentation/public-boundary.md).

Contributions must not contain:

- student or colleague personal information;
- private institutional or Moodle material;
- credentials, tokens, local configuration, or private keys;
- third-party assets without documented provenance and redistribution rights;
- Git history copied from a private repository without explicit review.

Git commit names and email addresses become part of public history. Contributors
who want email privacy should use a GitHub-provided no-reply address.

## Contribution licences

By contributing material that you have the right to submit, you agree that:

- code contributions are provided under `GPL-3.0-only`;
- original educational-content contributions are provided under
  `CC-BY-SA-4.0`;
- file-specific third-party licences and attribution notices remain in force.

See [`LICENSE.md`](LICENSE.md) before submitting mixed code and content.

## Working practice

- Start from an issue or a recorded tracker item.
- Keep commits atomic and use descriptive conventional-style subjects.
- Add or update tests for code changes.
- Validate Markdown links and front matter for content changes.
- Record sources, licences, and modifications for imported assets.
- Update the canonical progress tracker and work log when a milestone changes.
- Do not push generated builds, virtual environments, caches, or secrets.

The detailed acceptance criteria and ordered project commit sequence are in
[`unexpected_professor_hub.md`](unexpected_professor_hub.md).
